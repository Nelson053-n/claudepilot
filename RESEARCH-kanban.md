# Канбан для Claude Code агентов: ресёрч 6 источников → план для prof

## Разбор по источникам

### 1. NikiforovAll/claude-code-kanban (npm v4.11.0, MIT) — самый ценный для нас
Read-only веб-дашборд (Express + chokidar + ванильный JS), который **наблюдает** за нативной работой Claude Code, ничего не запуская. Это инженерно ближе всего к prof по стеку (vanilla JS, файловое наблюдение) и даёт лучшие переиспользуемые приёмы.

**Лучшие идеи:**
- **Канбан читает нативную систему задач** (`TodoWrite` пишет по JSON-файлу на задачу в `~/.claude/tasks/`), дашборд только наблюдает — задачи не дублируются.
- **Waiting-индикатор** (янтарная пульсация) для сессий, ждущих `PermissionRequest`/`AskUserQuestion`/`ExitPlanMode`, с **self-heal** маркера: снимается, если JSONL тронут после ts ожидания + grace 15с, протухает через 30мин.
- **Инкрементальный append-only парсинг JSONL** с per-path state `{ino,size,scannedUpTo}` — это **главный приём экономии IO/токенов** (см. ниже).
- **Context-window мониторинг** на сессию (бар green→yellow→orange→red, маркер 200K, разбивка input/output/cache, $).
- **Skill `kanban`** — сам Claude из сессии командует доской (open/pin/peek).
- Агенты `active/idle/stopped` через **last-line-wins** свёртку JSONL (лучше нашего одиночного `.rc`).

### 2. nimbalyst.com (статья «session kanban»)
Концептуальная статья: каждая агент-сессия = карточка, движется Backlog→In Progress→Waiting→Review→Done, статус выводится **автоматически из реального состояния агента**, не вручную.

**Лучшие идеи:**
- **WIP-лимит 3-5 активных сессий** — под пропускную способность ревью, чтобы не жечь токены на заброшенные прогоны (главный косвенный приём экономии).
- **Pre-planning**: писать карточку-ТЗ ДО запуска агента → меньше переспросов = меньше токенов.
- **git worktree на карточку** для изоляции параллельных агентов.
- **Local-first**: читать состояние сессий из локального `~/.claude`, не из облака.

### 3. Reddit-тред (реконструкция → langwatch/kanban-code и аналоги)
Карточка автоматически связывает Claude-сессию + git worktree + tmux + GitHub PR. Автодвижение по 6 колонкам по сигналам активности (хукам). Сам тред недоступен, фактура по совпадающим проектам.

**Лучшие идеи:**
- **Карточка = единый контейнер контекста** (сессия↔worktree↔tmux↔PR через `links.json`).
- **Детект статуса через Claude Code hooks** (`Stop`/`Notification`/`SessionStart/End`).
- **Background-reconciliation** orphaned-ресурсов по sessionId/branch/path (вместо polling).
- **leader-worker** (saltbo/agent-kanban): лидер декомпозирует, daemon диспатчит воркеров, atomic claims против гонок, stale-detection (offline >2ч).

### 4. langwatch/kanban-code (AGPLv3) — десктоп + CLI
«IDE 2026»: master-агент через CLI оркеструет параллельные сессии. Главная идея — снять context-switching bottleneck, централизуя контекст в карточке.

**Лучшие идеи:**
- **CLI для master-агента**: `kanban list --json` / `send <card> <msg>` / `capture <card>` / `status` (со сводкой по токенам/стоимости) — программная оркестрация.
- **BM25-поиск** по всей истории сессий (⌘K).
- **Reconciler-discovery вместо polling**; **lazy-loading** описаний PR.
- **Чекпоинты/форки сессий работают напрямую на файлах** (без API-вызовов = ноль лишних токенов).
- **Redux-style reducer** + port/adapter; KSUID — time-sortable id.

### 5. YouTube Eric Tech — «Auto Claude Kanban Boards»
Канбан как оркестратор: drag в In Progress спавнит агента. Транскрипт недоступен, фактура по vibe-kanban/Nimbalyst.

**Лучшие идеи:**
- **Каждая карточка скоупит ровно нужный контекст** — агент не тащит лишние файлы, не жжёт токены на нерелевантное (главный прямой приём экономии).
- **Inline code review** в UI: дифф + фидбэк агенту не выходя из доски.
- **WIP 3-5** + ревью перед запуском нового — меньше переделок.
- Мульти-агентность (Claude/Codex/Gemini/Copilot), follow-up в активную сессию.

### 6. YouTube Ryan MacLean — «Auto Claude» (AGPL-3.0, на Claude Agent SDK)
Автономный multi-agent SDLC-фреймворк: plan→build→**validate**, канбан-UI. Фактура реконструирована.

**Лучшие идеи:**
- **Авто-валидация** как фаза SDLC (фреймворк сам прогоняет тесты).
- **Loadable skills на репозиторий** — узкий task-specific контекст вместо монолитного промпта.
- **Sentinel/markdown-файлы состояния** (`.agentkanban/`, `AGENTS.md`) — реинъекция контекста без LLM-вызовов.
- **Детерминированная координация после первичной декомпозиции = ноль токенов на оркестрацию** (отмечено как самый экономный паттерн).
- Авто-PR + автозакрытие по merge через GitHub webhook.

## Лучшие решения для внедрения (приоритет польза/усилия)

1. **Стриминг прогресса агента** через `--output-format stream-json` + SSE. Подтверждено: `claude -p` поддерживает stream-json. Фундамент для live-токенов, waiting-детекта и ранней остановки зомби.
2. **Waiting-детект** через хуки (`Notification`/`PreToolUse`) + self-heal маркера. Хуки в `~/.claude/settings.json` уже настроены (SessionStart/PostToolUse/SessionEnd) — расширить дёшево.
3. **Авто-валидация результата** (детерминированная: pytest/git diff/py_compile) перед колонкой «Готово» — ловит мусорный `rc==0` без доп. токенов.
4. **Парсинг live-сессий** `~/.claude/projects/*.jsonl` — обзор ВСЕЙ работы Claude Code, не только prof-задач.
5. **Глобальный учёт токенов** из live-сессий по проектам/дням — нельзя оптимизировать нерезмеренное.
6. **CLI + Skill для master-агента** — само-оркестрация (декомпозиция → подзадачи в prof).
7. **WIP-лимит**, **Telegram-пуш**, **дедуп авто-анализа**, **безопасный markdown** — быстрые победы.

## Оптимизация расхода токенов (сводный раздел)

Приёмы из источников, ранжированные по применимости к prof:

1. **Скоупить контекст в карточке** (все источники): узкий task-specific промпт вместо длинных свободных диалогов — короче промпт, меньше уточняющих итераций. → реализуется через дедуп + pre-planning в авто-анализе.
2. **WIP-лимит 3-5** (Nimbalyst, Eric Tech): не плодить заброшенные параллельные прогоны, жгущие токены и квоту 5h/7d.
3. **Детерминированная координация после декомпозиции = 0 токенов** (Auto Claude): master-агент декомпозирует ОДИН раз, дальше CLI/детерминированный диспатч — оркестрация не стоит токенов.
4. **Авто-валидация без LLM** (Auto Claude): тесты/линт/git diff детерминированно — ловит провал ДО дорогого слепого повторного prompt-цикла.
5. **Бюджет-гард по usage** (наш `get_usage` уже есть): не запускать анализ/задачи при 5h-util >85%.
6. **cache_read мониторинг**: высокий cache-hit = экономия; подсветить проекты с низким cache-hit / высоким output на задачу как кандидаты на оптимизацию промптов.
7. **Дедуп предложений авто-агента**: не предлагать (и не запускать) то, что уже стоит на доске.
8. **Инкрементальное дельта-чтение JSONL** (claude-code-kanban): не токены модели, но 0-IO на горячем пути — критично при парсинге ~сотен сессий.

## Чего prof не хватает по сравнению с лидерами

| Возможность | Лидеры | prof | Приоритет |
|---|---|---|---|
| Стриминг прогресса агента в реальном времени | ✅ все | ❌ слеп до `.rc` | **высокий** |
| «Ожидает ввода/разрешения» (Waiting) | ✅ kanban-code, Nimbalyst | ❌ | **высокий** |
| Авто-валидация результата (тесты/линт) | ✅ Auto Claude, vibe-kanban | ❌ `rc==0`=done | **высокий** |
| Парсинг нативных live-сессий `~/.claude` | ✅ claude-code-kanban, agent-viewer | ❌ только свои задачи | **высокий** |
| Глобальный учёт токенов (все сессии) | ✅ | ❌ только prof-карточки | средний |
| CLI/Skill для master-агента | ✅ kanban-code, claude-code-kanban | ❌ | средний |
| WIP-лимит | ✅ Nimbalyst | ❌ | средний (дёшево) |
| Push-уведомления | ✅ kanban-code (Pushover) | ❌ | низкий (дёшево) |
| git-worktree-изоляция на задачу | ✅ почти все | ❌ запуск в живой папке проекта | средний |
| Context-window/200K мониторинг сессии | ✅ claude-code-kanban | ❌ | низкий |
| BM25/full-text по истории сессий | ✅ kanban-code | частично (vector по памяти) | низкий |
| Multi-agent team-config | ✅ | ❌ | низкий |

**Сильные стороны prof, которых у многих лидеров нет:** реальный учёт стоимости по задаче из `total_cost_usd`, раздел «Затраты» по проектам, usage-бар 5h/7d из oauth/usage (готовый бюджет-гард), векторный поиск по памяти проектов, авто-агент анализа слабых мест с approve-флоу, голос. prof — единственный со связкой «канбан + долговременная память проектов + векторный поиск».

**Главный архитектурный вывод:** prof силён в *учёте и долговременной памяти*, но слеп в *реальном времени*. Рекомендации 1-5 закрывают именно слепоту (стриминг, waiting, валидация, парсинг live-сессий, глобальный учёт токенов) — и все ложатся на текущий стек без смены технологий: те же `claude -p`, FastAPI SSE, append-only файлы в `runs/`, чтение `~/.claude/projects`.
